02 / THE DELIVERY CHAIN

Five stages. One release.

AUDITABLE / REPRODUCIBLE
01
SOURCE CONTROL

Commit & Pull Request

Push code or open a pull request. GitHub Actions starts validation automatically, before the release package is built.

git push origin feature/my-change
02
QUALITY GATE

Tests & Site Audit

Python 3.11 and 3.12 run all application tests. Node.js verifies JavaScript. A custom auditor checks every HTML page and its internal links, images, scripts, and styles.

python projects/ci-cd-pipeline/pipeline.py check
03
RELEASE ENGINEERING

Package & Verify

Once tests pass, Python creates a deterministic ZIP of the website, calculates SHA-256 checksums for each file, verifies the archive, and uploads it as a downloadable GitHub Actions artifact.

python projects/ci-cd-pipeline/pipeline.py build
04
PRODUCTION DELIVERY

Publish to GitHub Pages

The existing GitHub Pages branch source automatically publishes main/docs. This hosting path is separate from our CI artifact and does not require a paid build service.

main → docs/ → GitHub Pages
05
DEPLOYMENT MONITORING

Public URL Smoke Test

A follow-up workflow checks that key public pages load over HTTPS and contain expected content. A failure is reported in GitHub Actions.

python projects/ci-cd-pipeline/pipeline.py smoke
Deployment architecture note

GitHub Pages currently deploys directly from main/docs. CI runs independently, so a failed test does not block the automatic Pages publication. This project provides an artifact quality gate and post-publication verification. A strict blocking deployment gate would require switching Pages to GitHub Actions and enforcing branch protections.
